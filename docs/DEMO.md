# 評審操作指南

1. 在根目錄執行 `npm ci`、`npm run db:migrate:local`、`npm run dev`。
2. 開啟 `http://localhost:3000`，點選進入工作區。開發環境的 Sites 外掛提供本機測試身分；正式環境必須使用真實 Sites 登入。
3. 到「AI 付款協作」，選「重現已錄製推論」。不必下載模型，不必提供 API 金鑰。三個部門的原始理由、時間、模型與完整回應會顯示在卡片中。
4. 點「查看付款清單」，查看多筆提案合併後的風險、金額與狀態。所有新意圖都是 HELD。
5. 點審核，核對每筆資料與預估資金緩衝，填寫理由並確認，核准後重新開啟同一批確認狀態已保存。
6. 到「稽核與證據」執行驗證、重播檢查，下載完整證據。九項完整性檢查應通過。

## 重現流動性拒絕

在「工作區設定」把資金底線設為 **90%** 並保存，再重現一次 AI 推論。此新批次有 US$5.4m 提議流出，整批緩衝 83.125%，低於政策。先核准三筆關鍵薪資，共 US$2.7m；預計保留 91.5625%。之後再核准五筆時，清單包含額外付款，累計會突破該批 US$3.2m 預算，按鈕將被停用。直接送同樣請求到 API 也會收到 422，原批次狀態不變。

上述數字來自隨作品附帶的首次實際模型紀錄；即時模型可能作出不同選擇，應以畫面與證據顯示的數字為準。完成後可把工作區底線改回 75%；已建立批次仍保留其 90% 快照。

## 即時模型

另開終端執行 `ollama pull qwen3.5:4b`，確認 Ollama 服務已啟動，再點「執行即時 AI 工作流」。每個代理上限 60 秒；全部完成並驗證後才儲存。重新載入可讀回已保存批次，傳輸失敗後重試使用相同 requestId。請勿在尚未取得模型時把重現模式稱為即時 AI。

首次原始推論也可由 `node --experimental-strip-types scripts/record-agents.ts` 重新取得。此命令會更新本機 recording 檔案，供開發者檢驗；已發布版本的紀錄不會因此改變。

## 展示失敗備援

- 網路或模型無法使用：選擇清楚標記的「重現已錄製推論」。
- 線上展示網址不可用：依 README 在評審自己的電腦執行；不要把 localhost 填入公開展示網址欄。
- 截稿前以 YouTube 影片和公開程式為主，兩者均必須可匿名觀看。不要把建置成功當成影片上傳成功。

## 新版自訂發票與逐筆核准

1. 啟動 Ollama 後，到 AI 付款協作切換「自訂發票清單」。
2. 載入六張示範發票或貼上 AI 專用 CSV，修改 ID、金額、到期條件；設定每部門預算。
3. 欄位預覽通過後執行，原始提示、輸出及輸入清單會保存。這次會真正呼叫模型。
4. 到付款清單，勾選特定一筆，再核准。可以使用「選出額度內建議」預選，但仍需人員核對、填寫理由及確認。
5. 匯出證據後，開啟 `/verify` 或工作區下方的「獨立驗證證據檔」。選檔或貼上 JSON，九項重算應通過；非 AI 批次的模型檢查為不適用。

一般 CSV 和情境建立支援相同 requestId 的安全重試。遇到連線中斷時保留原內容重試，先核對已保存的批次；不要改名或改發票後把它當作同一個請求。
