## 為什麼題目仍有價值，但不宜宣稱首創

[BIS Working Paper 1310](https://www.bis.org/publications/working-paper-1310-ai-agents-cash-management-payment-systems) 已研究生成式 AI 在支付系統內管理現金、流動性限制與付款優先順序。英國央行的 [2026 年 7 月金融穩定報告](https://www.bankofengland.co.uk/financial-stability-report/2026/july-2026) 也介紹 Project Logos，觀察模擬金融市場中的 LLM 代理。這些證明研究問題具相關性，也表示「AI 群體行為／財務模擬」本身不足以形成獨特性。

HerdBrake 最清楚的切入點是：**將多筆代理付款意圖放在一起檢查，在核准前約束累計資金風險，並保留可重算的審核證據。** 本次真正補強的是「連續核准也無法突破政策」。這比只有警示數字更容易展示，也能給評審可重現的反例。

目前的 30 筆代理意圖是固定規則產生的合成資料，不是 30 個 LLM。WebMCP 有註冊操作入口，但不等於已證明模型會正確推理或降低真實風險。SHA-256 事件鏈也不等於鏈上簽章、智能合約或不可變存證。

## 截稿前的投入順序

1. **提交資格**：確認可匿名讀取的 GitHub／GitLab、實際授權檔案、README 重現步驟、來源揭露與兩分鐘影片。準備稿在 [SUBMISSION.md](SUBMISSION.md)。公開程式碼與影片需要明確選定發布位置及授權；本次只準備文件，沒有代為公開或投稿。
2. **真實 AI 主線**：讓一個可指認的模型讀取明確的合成金融訊號，透過結構化輸出產生付款意圖；保存模型／提示／輸出／失敗情形，經原有規則和人工覆核後才變更核准狀態。沒有 API 憑證或真實呼叫紀錄時，不以預錄字串冒充。
3. **量化使用者價值**：找財務／出納使用者測一次原始流程與 HerdBrake，記錄漏看風險、操作耗時與理解成本。現有 60 組基準只能說明控制邏輯，不能報成節省損失或模型準確度。
4. **國泰獎項額外門檻**：若鎖定國泰，須補一條真實可驗證的測試網金融授權／重播拒絕流程及交易證據，再判斷資格；單純雜湊稽核目前無法支持「AI × 區塊鏈金融整合已完成」。
5. **展示穩定性**：目前 Sites 查詢既有專案回傳 not found，正式網址尚未驗證。先讓影片及 README 可完整重現本機流程；展示網址需另完成正確帳號／專案的部署與外部訪客驗收。

## 建議展示敘事

開場：「每筆付款都符合單筆限額，為什麼整批仍會把現金緩衝壓到底線以下？」

畫面依序呈現：30 筆合成意圖→整批預估保留 73.80%→政策底線 75%→核准五筆後仍保留 96.16%→過度核准被拒絕→下載帶政策與審核紀錄的證據。數字是工作區實測範例，明確標示合成資料，避免把已核准當成已付款。

我的建議是保留 HerdBrake 這條主線，把剩餘投入集中在真實 AI 串接、價值驗證與提交素材。以目前狀態去爭前三，我不會給樂觀保證；若能補上可重現的 AI→付款意圖→累計拒絕證據，作品會比一般財務儀表板更有辨識度。國泰獎項則還有明確的區塊鏈整合缺口。
