# 功能升級與實測驗收

驗收日期：2026-09-06（Asia/Taipei）。T066 我女友好正 · AI Agents & Automation。

本輪完成自訂 AI 發票、指定付款核准、建立批次的安全重試與瀏覽器獨立證據驗證。以下區分真實模型、實際 HTTP／資料庫操作、瀏覽器操作及自動化測試；不把測試替身當成模型實測。

## 這次實際修好的問題

| 原本限制／缺陷 | 完成後行為 | 驗證方式 |
| --- | --- | --- |
| AI 只能規劃內建十二張發票 | 可提供 1–24 張發票，最多 3 個部門、每部門 8 張；模型按部門產生 PAY／DELAY 與理由 | 真實 Qwen 呼叫、輸入邊界測試、原始回應與付款資料映射檢查 |
| 只能用數量與優先順序選核准範圍 | 可直接勾選確切付款 ID；額度內建議仍需人工確認 | 實際核准兩筆自訂付款；過時、重複、未知 ID 及數量不符的回歸測試 |
| AI 的部門預算只有提示作用 | 自訂批次保存預算；核准時檢查每部門累計額度，另受整批流動性底線限制 | SQLite 交易測試：超額拒絕且狀態、稽核版本不變 |
| 建立批次在網路結果不明時容易重複保存 | 情境、CSV、AI 建立使用綁定內容的 requestId；相同重送返回既有批次，換內容回 409 | 真實 HTTP 同時匯入只保存一批；重載恢復與帳號隔離測試 |
| 獨立驗證必須用命令列 | 公開 `/verify` 和工作區可在瀏覽器重算九項檢查；選檔或貼上 JSON 不會上傳 | 目前批次九項通過、錯誤 JSON 被拒絕、匿名 HTTP 200、CLI 與篡改回歸測試 |
| 核准成功後，新狀態與舊選取短暫共存會使畫面錯誤 | 舊選取安全失效並停用確認；後端已保存的結果能正常刷新 | 本輪實際操作發現、修正後再核准成功與重新載入驗證 |
| 自訂付款在建立與重新讀取時的順序可能不一致 | 以相同 ID 排序保存與回傳 | 新增持久化往返測試，修正後通過 |

輸入另外限制唯一發票 ID、必要欄位、CSV 大小、單筆金額和幣別；部門預算為 0.01 至 10 億美元，最多兩位小數。金額、幣別及目的地固定來自原始發票，模型沒有修改權限。

重試暫存只把輸入指紋、UUID 和時間保存在該分頁的 sessionStorage，最多 24 小時；不保存 CSV 內容。若重新載入，需要重新提供相同內容才能重用不確定的請求。相同 AI 請求同時抵達時仍可能觸發多次推論，但交易只保存一批，不能把它解讀為模型計算的 exactly-once 保證。

## 真實自訂發票操作

原始證據：[custom-ai-2026-09-06.json](custom-ai-2026-09-06.json)。這是當次即時模型與本機 D1 的完整匯出，使用明確標示的合成驗收資料。

- 模型：`qwen3.5:4b`，Ollama，三個獨立部門工作階段；六張發票，沒有使用測試替身。
- 紀錄時間：2026-09-06 04:30:23 台北時間；三次呼叫合計約 20.7 秒，不含使用者操作時間。

- 在畫面明確指定並分兩次核准 `QA-TPE-01`（US$500,000）與 `QA-HSC-01`（US$600,000）。重新載入後 2 RELEASED、4 HELD，累計核准 US$1,100,000，尚可核准 US$6,900,000，保留 96.5625%。
- 下載後 CLI 九項全部通過；工作區在瀏覽器重新計算九項亦全部通過。
- 末端稽核指紋：`6996bc158add76b3a5400e043bab291cae8b972539d81576d915b673ae598f51`。
- 證據包指紋：`3f59920e3e2d4bce190455ad0665d3aa0d965e741bd6239fffaaa1c33e526a37`（包內 canonical payload 指紋，非 JSON 檔案位元組雜湊）。

原始模型曾提出「可等待下月預算釋放再付款」，但發票沒有提供下月預算資訊。這個沒有依據的推論原樣保留，不能稱為最優付款建議或完全正確的理由。人工應檢查到期條件；程式的金額與政策限制獨立執行。

## 程式與 HTTP 驗證

本機 Node 26.8.1，`npm run check` 成功：lint、嚴格型別、67 個純邏輯／SQLite 測試、正式建置。`npm run test:api` 的 8 個 HTTP 整合測試全部通過，對象為既有本機開發 Worker 與 D1，並非正式部署。

新增測試涵蓋：重新載入恢復請求身分、帳號隔離、同時建立與不同內容重送、過時政策、確切核准 ID、過時 UI 狀態、自訂 CSV 與預算邊界、模型原文與固定發票映射、累計部門限制。模型回歸測試使用明確的測試替身；上一節才是真實推論證據。

公開 [Quality checks](https://github.com/nrps9909/herdbrake/actions/workflows/check.yml) 在 Node 24 從鎖定檔安裝，執行相同 67 個測試、建置、D1 遷移及 8 個 HTTP 整合。查看所提交 commit 對應的執行結果；舊報告中的 CI 連結不代表本輪程式。

可自行重算：

```bash
npm ci
npm run check
npm run db:migrate:local
npm run test:integration
node --experimental-strip-types scripts/verify-evidence.ts docs/acceptance/custom-ai-2026-09-06.json
```

執行 integration runner 前停止手動 dev server；若已開啟本機開發服務，改用 `npm run test:api`。團隊 ZIP 的 `verification/` 另附其來源提交及乾淨解壓驗證結果。
