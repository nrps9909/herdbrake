# HerdBrake 全端驗收 · 2026-09-05

本次驗收範圍是本機個人財務審核工作區：登入、匯入、聚合評估、人工核准、持久化、查詢與證據匯出。沒有加入計費。測試資料皆為合成資料；核准不移轉資金。

## 結果

- `npm run check`：lint、TypeScript、51 個單元／SQL repository 測試、正式 build 通過。
- `npm run test:api` 與獨立啟動的 `npm run test:integration`：6 個本機 Worker／D1 整合測試通過，涵蓋全部六種情境、真實 D1 交易、並行請求、登入與偽造標頭拒絕、CSRF、匯入／政策衝突、搜尋與下載，以及累計流動性拒絕。
- `node --experimental-strip-types scripts/benchmark.ts`：60 個合成案例、1,800 筆意圖，原始清單 4 個案例低於底線，逐筆核准控制後 0 個。完整數據在 [synthetic-benchmark.json](synthetic-benchmark.json)。這是規則不變量檢查，不是 AI 準確度、因果推論或真實客戶效益。
- 瀏覽器：桌面 1280×720、手機 390×844 的首頁及七個功能頁；平板 768×1024 加驗總覽。使用實際瀏覽器 UI、DOM 與截圖驗收。修正後手機各頁根元素寬度與捲動寬度相同；表格保留區域內水平捲動。
- 開發相依預先最佳化後，自 18:11:30 起的本次操作未出現新的瀏覽器 error / warn。初次冷啟動曾發生 React 版本化 chunk 不一致，已修正並重啟驗證。

## 本次發現並修正

1. **核准未累計資金**：後端現在把先前所有已核准流出加回本次預算；超額回傳 `422 HB_LIQUIDITY_FLOOR`，整筆不寫入。金額使用十進位比例與整數美元分計算，換匯不足一分向上保留；DELAY／BUFFER 不占流出預算。單筆政策上限也在核准與情境建立時檢查。
2. **缺乏可比較的核准結果**：清單加入整批全部執行、目前核准範圍、累計流出與剩餘額度。審核視窗清楚列出本次流出和超額原因；每次成功授權保存當時的流動性檢查。
3. **檔案更換競態**：新檔案讀取開始即清掉前一份預覽，版本檢查避免較慢的舊讀取覆蓋新資料；超限檔案無法誤送前一份內容。
4. **CSV 下載未落地**：原導覽式下載在本次內嵌瀏覽器未產生檔案。已改為明確請求、錯誤顯示與檔案下載；最後確認下載的 CSV 包含三筆、三種幣別及引號欄位。
5. **手機溢出與搜尋**：把表格輔助文字限制在捲動容器內；快速搜尋改成簡潔清單；搜尋圖示加入可讀名稱；手機輸入文字為 16px。
6. **錯誤恢復**：明確被後端拒絕的核准不再當成可能已成功的請求而鎖死表單；暫時連線故障仍維持原 idempotency key。
7. **冷啟動**：預先最佳化共用 UI／React 依賴；型別檢查關閉增量快取，避免歷史錯誤快取污染驗證。

## 上線邊界

這份成果是已驗證的本機程式與資料庫流程。本次沒有發布或改變網站受眾，也沒有遠端 CI 執行結果。依現有 hosting manifest 查詢 Sites 時回傳 `project_not_found`，因此不能確認既有正式站狀態，更不能把本機通過當成線上完成。

額度以單一批次為界，未連接共用銀行帳戶餘額。工作區屬個人所有，未提供多人組織、雙人覆核、即時匯率、銀行／錢包付款、線上 LLM 決策或區塊鏈結算。建立新批次的重送目前仍可能建立另一批次；核准操作才有完整 idempotency 保護。雜湊鏈提供內容一致性檢查，沒有外部錨定或不可變儲存保證。這些範圍需要另以實際整合與正式環境驗收確認。
